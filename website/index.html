Kernel Boundaries

macOS Seatbelt & Linux Landlock

Unlike web-based or shell wrappers that execute commands directly in your user space with unrestricted access, Octane wraps process execution in kernel sandboxing rules.

  • Read-only guards: Prevents alteration of .git/, .octane/, and core configuration paths.
  • Workspace restriction: Confines write operations exclusively to designated working directories.
  • Network restrictions: Restricts subprocess sockets according to explicit policy rules.
octane-sandbox / seatbelt.rs 
pub fn apply_seatbelt_profile(workspace: &Path) -> Result<()> {
    let profile = format!(
        r#"(version 1)
(deny default)
(allow file-read* (subpath "{}"))
(allow file-write* (subpath "{}"))
(deny file-write* (subpath "{}/.git"))"#,
        workspace.display(), workspace.display(), workspace.display()
    );
    Seatbelt::enforce(&profile)?;
    Ok(())
}

Delegated Execution

Concurrent Subagent Delegation

When complex multi-step tasks arise, the main agent spawns dedicated subagents with specific personas and clean context boundaries.

  • code agent: Implements well-specified changes end-to-end.
  • critic agent: Reviews code proposals to spot edge cases and security flaws.
  • research agent: Explores large codebases and gathers facts without polluting context.
  • test agent: Executes tests, collects exact stack traces, and verifies fixes.
octane-context / delegation.rs 
pub async fn run_subagent(agent_type: AgentRole, prompt: &str) -> Result<Report> {
    let mut subagent = Subagent::new(agent_type);
    subagent.isolate_context();
    let report = subagent.execute(prompt).await?;
    Ok(report.summarize())
}
